## Story

### Start

上学期游泳课上我突然觉得头晕目眩恶心，在网上一番搜索和让AI进行了一番闻问，我诊断自己是颈源性头晕。清明节前后我去玉泉医院挂了骨科，照了MR后发现果然是颈椎压迫神经导致晕眩，在进行了两周推拿和针灸后基本康复。医生提醒我特别需要注意活动颈椎，避免长期低头伏案导致复发加重。

起初我还是很注重活动的，但是很快我就好了伤疤忘了疼；我早就想写一个类似番茄钟的项目来通过弹窗提醒自己做运动。暑假实习期间正好时间充裕就想着重新弄一下。

### Dev

因为我的 Gpt 订阅到期了，所以我不得不找免费替代。我的vibe工具链配置是 Claude Code 加学校免费提供的 GLM-5.2 api，用 cc-switch 做了中转代理。为了提升 agent 能力，使用了 superpowers 系列的skill。

### Rust？

实习期间我花了两天时间翻看了「Rust 圣经」和 「跟着案例学 Rust」，之前也听说过不少 Rust 高安全性和高性能的神奇故事，又了解到 Codex，CC 这些ai工具都是使用 Rust 开发的。我头脑发热了，开始产生了幻想，希望开发一个只用几个MB就能运行的高性能项目。（这里开始走歪了，其实我是想要一个好看好用的软件而不是一个极客软件）

我电脑里本身有 Rust 工具链，在和 cc 说清楚了要用 rust 开发后，他提供了 Rust 和 Tauri 的技术栈。（ai的原评价为极客风）

```markdown
## 2. 技术栈（精确版本）
- **前端**：纯 HTML5 + CSS3 + JavaScript（不使用 React/Vue/Svelte 等框架）。
- **后端**：Rust（Edition 2021）。
- **GUI 框架**：Tauri v2（最新稳定版）。
- **异步运行时**：Tokio（使用 `tokio::sync::mpsc` 和 `tokio_util::sync::CancellationToken`）。
- **状态管理**：`Arc<tokio::sync::Mutex<AppState>>`。
- **动画资源**：Lottie Web（JSON 格式）或 GIF。为了清晰度，优先使用 Lottie 矢量动画。
```

然后ai开始vibe coding，开了 auto mode 哐啷哐啷搞了半个小时后出了个结果，我一打开发现是石。整个逻辑倒是没有问题，但是gui风格太丑了，排版还是很差。

再继续让ai迭代几轮，还是没法调成我预想的样子。而且ai花了很多时间去解决rust的编译问题（和人类一样）。作为一个小项目，花费这么多时间去搞这些完全买椟还珠了。

**DeepSeek 锐评**

用 Rust 写桌面工具，简直就是开着一辆F1赛车去小区门口买酱油——油烧了大半箱，酱油瓶还不知道往哪放。 这不是你的问题，是 Rust 在 GUI 领域本来就还在“驾驶培训阶段”。

### Electron

我直接扬掉了原来 ticktockneck-rs 的所有内容，重开了一个新项目，这次我放任ai自己选择技术栈，然后就变成 PyQt/Electron/C# 三选一。由于我的电脑上已经有很完整的 Node.js 工具链（这个网站就是用Astro和Node.js开发的），但是我的C#工具链不完整还要安装，所以直接选择 Electron，拥抱JavaScript。（虽然我早就听说Electron往自己里面塞Chrome内核，但是哥们儿内存和磁盘也不小所以无所谓，先跑起来再说）

AI 一顿猛操作很快就 vibe 出来了，效果拔群，gui也不赖，再根据我的要求调整了几轮后已经非常满意。使用过程中遇到了bug反馈后很快解决，顺手还优化了一波性能，增加了一些小功能。我超级无敌万倍大喜过望欢呼雀跃喜上眉梢，然后就开始正常使用。虽然最后exe竟然有70MB，但整个过程非常愉悦而且电脑还有500G存储，完全hold得住。

## Reflection

以下内容完全是个人暴论，大家批判性理解，欢迎和作者讨论～

在古法编程时代，初级开发者很难在早期就触碰到一门语言的性能边界，也因此很难真正感知不同语言在生态、社区支持与设计哲学上的差异。那时，你必须先驾驭住一种语言——能看懂文档、写得下代码、捉得了虫——然后才谈得上去比较不同技术框架与栈的优劣。

但 coding agent 的爆发，把所有人都拉上了“高手桌”。（欢迎来到高手如云的时代）当 AI 能轻松驾驭各种复杂语言时，技术栈的上手难度和驾驭门槛，反而成了权重最低的考量因素。毕竟几家旗舰模型都能写、能调、能重构，语言本身已经不再是开发的瓶颈。

于是问题变成了：在 AI 时代，我们该用什么标准来选择技术栈？我的看法是，优先级应该转向生态支持、可扩展性、性能是否贴合你的最终目标。良好的生态和充足的文档，能极大降低 AI“胡搞”的概率；虽然 AI 力大砖飞，手搓轮子也不是不行，但那意味着你将经历反复调整、试错、重新评价的漫长循环——本质上是用人的时间换 AI 的自由度。

同样是一个“右上角弹窗+毛玻璃+Lottie动画”的桌面工具，用 Rust+Tauri 让 AI 来写，它需要在 CSP 策略、资源路径、异步生命周期和 Send/Sync 约束之间反复横跳，编译错误一个接一个；换成 Electron，AI 三下五除二就能搞定。不是 Rust 不强，而是它在这个场景下的生态摩擦太大了。AI 强归强，但“大炮打蚊子”式的技术栈，它照样打得满头包。

反过来，当技术栈和需求匹配时，AI 的表现会丝滑得多。选对了，AI 是你的协作者；选错了，AI 就成了你的实习生，而你变成了它的代码审查员。

无论 AI 如何进化，工具都应该围绕人展开，服务于人的需求。AI 可以帮你搓轮子，但成熟框架能帮你省下反复折腾的时间。
